# CALDER

[Chinese](README.md) | [English](README_EN.md)

CALDER is a multi-feature fusion model for AI-generated text detection. Users provide only text and labels. The package internally extracts, aligns, aggregates, and caches semantic, token-probability, alignment-imprint, document-statistical, and compression/codelength features.

CALDER does not use the final scalar output of a training-free detector such as LAPD, LastDE, or DetectGPT as a model input.

## 1. Installation

```bash
git clone https://github.com/try2love/CALDER.git
cd CALDER

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

Frozen observer models are downloaded from Hugging Face on first use; their weights are not stored in this repository. Llama-2 requires model access approval and Hugging Face authentication:

```bash
hf auth login
```

Official Hugging Face CLI documentation: <https://huggingface.co/docs/huggingface_hub/guides/cli>

## 2. Training data

Training and development splits may be JSONL or CSV. Each record needs only text and a label.

```jsonl
{"sample_id":"train-0001","content":"This article was written by a person.","label":0}
{"sample_id":"train-0002","content":"This passage was generated by an AI system.","label":1}
```

`text` is accepted as an alias of `content`. Labels may be `0/1` or `human/AI`. The canonical direction is human=`0`, AI/machine=`1`. `sample_id` is optional. Both training and development splits must contain both classes.

## 3. Train with one Python command

```bash
python -m benchmark_fusion train \
  --train data/train.jsonl \
  --dev data/dev.jsonl \
  --output outputs/calder_run
```

This command validates the text records, loads all frozen observers, right-truncates each observer input to 1024 tokens, builds all eight CALDER tensors, stores reusable features under `outputs/calder_run/.cache/`, computes normalization moments from the training split only, trains the five-branch fusion model, applies dev-AUROC early stopping, retains only `calder_model.pt`, and freezes the development classification threshold.

Defaults are seed 42, learning rate `3e-4`, batch size 128, hidden size 128, adaptive-gate fusion, at most 20 epochs, and patience 4.

Two GPUs are recommended for base/aligned observer pairs:

```bash
python -m benchmark_fusion train \
  --train data/train.jsonl --dev data/dev.jsonl \
  --output outputs/calder_run \
  --devices cuda:0,cuda:1 --train-device cuda:0
```

With one GPU, the aligned observer can run on CPU, at substantially lower throughput:

```bash
python -m benchmark_fusion train \
  --train data/train.jsonl --dev data/dev.jsonl \
  --output outputs/calder_run \
  --devices cuda:0,cpu --train-device cuda:0
```

## 4. Classify plain text

```bash
python -m benchmark_fusion predict \
  --model outputs/calder_run/calder_model.pt \
  --text "Paste the text to be detected here."
```

The package reuses the observer configuration stored in the trained bundle and returns:

```json
{"sample_id":"input-0001","ai_score":1.27,"ai_probability":0.7807,"prediction":"AI"}
```

`ai_score` is the AI-positive logit. `ai_probability` is its sigmoid value. `prediction` uses the threshold frozen on the development split during training.

Classify a TXT file:

```bash
python -m benchmark_fusion predict \
  --model outputs/calder_run/calder_model.pt \
  --text-file article.txt \
  --output predictions.jsonl
```

Batch-classify JSONL or CSV:

```bash
python -m benchmark_fusion predict \
  --model outputs/calder_run/calder_model.pt \
  --input data/to_detect.jsonl \
  --output predictions.jsonl
```

Batch prediction records need only `text` or `content`; labels are optional.

## 5. Default frozen observers

| Purpose | Model |
|---|---|
| Semantic spans | `answerdotai/ModernBERT-base` |
| Probability/alignment | `meta-llama/Llama-2-7b-hf` + `meta-llama/Llama-2-7b-chat-hf` |
| Probability/alignment | `tiiuae/falcon-7b` + `tiiuae/falcon-7b-instruct` |
| Document probability/codelength | `openai-community/gpt2` |
| Model-scale/codelength | `openai-community/gpt2-large` |

Model IDs and revisions are stored in `calder_model.pt` and `observer_config.json`. Local model paths can be supplied with a custom observer configuration and `--local-files-only`.

## 6. Resource requirements

The trainable CALDER fusion network is small, but complete feature extraction runs several frozen observers. The default profile recommends two GPUs with at least 24 GB each. CPU-only and one-GPU-plus-CPU execution are supported but slow. Observers are loaded and released by stage; all six causal observers are not kept in GPU memory at once.

## 7. Code map

- `src/benchmark_fusion/text_features.py`: raw-text feature extraction and aggregation;
- `src/benchmark_fusion/calder_model.py`: five-branch CALDER architecture;
- `src/benchmark_fusion/text_cli.py`: training and plain-text prediction commands;
- `scripts/`: lower-level frozen paper-protocol entry points.

The internal tensor definitions are documented in [INPUT_SCHEMA.md](INPUT_SCHEMA.md). Users do not prepare NPZ files themselves.

## 8. Tests

```bash
python -m unittest discover -s tests -v
```

Tests do not download large models. A controlled fake observer validates record parsing, feature handoff, training, model reload, and plain-text prediction.

## 9. Release boundary

The repository includes the raw-text feature-extraction, CALDER training, and inference code. It does not include datasets, data splits, pretrained observer weights, trained CALDER checkpoints, predictions, experiment results, dashboards, or paper sources. External observer access rules and licenses remain governed by their publishers.
